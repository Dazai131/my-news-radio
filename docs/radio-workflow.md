# ニュースラジオの運用

## 現在のモード：非公開の試験運用

2026年11月9日、ユーザーは最初は非公開で進めることを指定した。
明示的な公開指示があるまで、ローカルの試聴版を作成し、このチャットに音声と結果を返す。
GitHubの更新前にはprivateでありPagesも無効であることを確認する。確認できない場合はローカル保存だけにする。
Publicへの変更やPages・Sites・Netlifyでの一般公開を行わず、公開設定をユーザーへ促さない。
試聴Webサーバーは127.0.0.1だけで待ち受ける。
以下に記載する一般公開の手順は、ユーザーが後で公開を明示的に指示した段階にのみ適用する。

## 番組の条件

- 日本語。AI・3D制作・PC・ゲームが対象。国内外のニュースを扱う。
- 毎朝8時（Asia/Tokyo）に作成と更新を開始する。完了まで数分以上かかる場合がある。
- 音声の実測時間は5〜10分。通常は4〜6本のニュース。
- このチャットがニュース収集、台本作成、PC音声の生成、GitHubへの更新を担当する。
- 音声生成と自動実行中はPCとデスクトップアプリを起動しておく。
- 日本語音声はMicrosoft Haruka Desktop。別の声へ変更する場合はクレジットも合わせる。
- キャラクター素材は現在のcharacter/を維持する。ヘッドホン・チョーカーなし、リボンは左右各1個、袖のピンク横線なし。

## ニュース収集と編集

企業・開発元の公式発表、公式リリースノートを優先して実際に検索し、記事を読む。
公開日と出来事の日付を区別する。直近24時間を優先し、週末などは72時間程度まで広げ、古い話題は日付を明示する。
既存episodesの出典URLを確認し、同じ発表の繰り返しを避ける。
発売予定や予告を公開済みと表現しない。推測、分析、メーカーの主張を事実と分ける。
分量合わせの繰り返しや、確認できないニュースは入れない。出典・公開日を私用ログに残す。
記事の長文転載は行わず、自分の言葉で要約する。画像は保存せず、出典のOGP画像URLが確認できた場合のみリンクカードに使う。
台本にこのチャットの個人的な会話、メールアドレス、秘密情報、PCのユーザー名や絶対パスを含めない。

## 台本から音声を作る

AGENTS.mdとdocs/formats.mdの形式を維持する。各文はsayとshowを持つ。
sayには日本語音声で自然に読める読み仮名、showには正しい製品名と表記を使う。
例：tools/radio/render-voice.ps1 -EpisodePath <台本JSON> -OutputDir <WAV一時フォルダ>
続けてPythonでtools/radio/assemble_episode.py <台本JSON> <WAV一時フォルダ> <サイトフォルダ>を実行する。
Python側はlameenc==1.9.0が必要。既存の作業環境に導入済みのものがあれば再利用する。
各文を個別に合成し、そのPCM長から字幕と場面切替を計算する。出力は1回分のMP3と時間情報入りJSON。
5〜10分、無音でないこと、ファイル参照と時間軸の整合性を検査する。初回はブラウザーで再生を確認する。

## GitHubへの反映

対象はDazai131/my-news-radio。毎回AGENTS.md、最新のmainとgh-pages、station.json、episodes.jsonを読み直す。
GitHub接続の認証を使い、ユーザーに手動アップロードや毎日のGit操作を求めない。
mainには設定、台本、放送一覧、運用用のコードだけを保存する。MP3をmainにコミットしない。
更新は可能ならGit treeとcommitで一括作成し、expected_sha付きのref更新で同時編集を保護する。
初期のお手本の放送は一覧から外す。以後の自局の過去の放送やユーザーの修正は維持する。

音声の公開にはgh-pagesを使う。mainの最新treeを基に、今回のMP3と直近30日分の音声blobを追加する。
直近30日分は既存gh-pagesのtreeからSHAを再利用できる。30日より前の音声を新しい公開treeへ引き継がない。
公開用commitの親は最新mainにする。gh-pagesの過去commitを親にし続けず、音声履歴の肥大化を避ける。
gh-pagesの更新は、取得したheadをexpected_shaとしてforce-with-leaseで行う。食い違った場合は読み直して判断する。
GitHub Pagesの公開元はgh-pages / (root)。リポジトリの公開範囲は勝手に変更しない。
無料プランでリポジトリが非公開の間は、データを準備してもPages公開は完了しない。
アップロード済み、定期設定済み、公開済みを区別し、公開URLの成功を確認するまで「公開できた」と報告しない。

## 音声blobの受け渡し

GitHubのcreate_blobはMP3をbase64として受け取る。ローカルファイルのbase64を画面に表示しない。
functionsの処理内でexec_commandの結果を受け取り、そのままcreate_blobへ渡せる。
1回のコマンド出力は約1MiBで切れるため、必要な場合はbase64を90万文字以下の固定長で分割して読み、
各出力の長さを検査して連結する。取得結果はtext()しない。encoding=base64で登録する。
ローカルのSHA-1（blobヘッダー付き）と返ったblob SHAが一致することを確認する。
テキストはcreate_treeのcontent、音声は作成済みblobのshaを指定できる。
認証情報を台本、ファイル、コマンド引数、会話へ書き出さない。

## 報告

日付、番組タイトル、実測時間、取り上げた話題、公開確認の結果を短くこのチャットへ返す。
公開設定が未完なら、その事実と必要な初回操作を伝え、音声の作成自体は続けてよい。
PCや接続の問題で作成できなかった日は、前日の放送を壊さず、失敗した段階を報告する。
